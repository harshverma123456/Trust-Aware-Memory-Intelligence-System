## 1. THE CORE PROBLEM (WHY DID WE BUILD THIS?)

In the real world, information is messy. If you ask an AI, "How much money did Startup A raise?", the AI shouldn't just Google it and give you the first answer it finds. 

Why?
- Blog A says $5 Million.
- The Wall Street Journal says $8 Million.
- A troll on Twitter says $0.
- Another blog says "five million dollars" (which is $5M, just written differently).

**Our System** acts like a master investigator. It takes a massive, chaotic stream of incoming "rumors" (claims) and carefully filters them to build an organized, trustworthy, and explainable Encyclopedia of Truth (the Memory Store).

---

## 2. THE 4-AGENT PIPELINE (THE WORKFLOW)

Every single rumor that enters the system goes through a strict assembly line manned by 4 distinct AI "Agents".

### 📂 THE PRE-GAME: HOW IT READS THE DATA
Before the Agents can even start, the main program (`main.py`) has to load the raw data.
1. **The Claims File (`claims 1 1 (1).jsonl`):** This file is formatted as JSON Lines (`.jsonl`), meaning every single line is a separate, standalone JSON object. The system opens the file and reads it line-by-line using Python's `json.loads()` function, pulling all 50 claims into memory as a list.
2. **The Schema (`schema 1 1.json`):** This file isn't actually processed by the code while it runs. Instead, we used this schema as a *blueprint* when writing the code. We looked at the schema, saw that every claim was guaranteed to have a `claim_id`, `claim_text`, `subject`, etc., and we built a strict Python `dataclass` to perfectly match this shape.

Once `main.py` has loaded the 50 claims, it hands them one-by-one to Agent 1.

### 🕵️ AGENT 1: THE EXTRACTOR (claim_extractor.py)
**The Job:** Read the raw, messy JSON data and organize it so the other agents can read it easily.
**What it actually does:**
1. It pulls out the `subject` (who the fact is about, e.g., "Startup A").
2. It pulls out the `object` (what the fact is, e.g., "$5M").
3. **The Timestamp Trick:** If a claim is missing a timestamp, the Extractor catches this. It secretly tags the claim with a warning flag (`timestamp_missing = True`) and sorts it to the very back of the line so that fresh, dated news gets processed first.

### 🔬 AGENT 2: THE VERIFIER (verification_agent.py)
**The Job:** Do a background check on the source and calculate a base "Confidence Score".
**The Math:**
1. **Base Score Calculation:** `Source_Reliability` (e.g., 0.85 for TechCrunch) multiplied by the `Label_Weight` (e.g., 1.0 if they are supporting the claim, 0.6 if they are refuting it). 
2. **The "Not Verifiable" Penalty:** If the claim is marked as a rumor without evidence, the Verifier cuts the confidence score exactly in half (multiplies by 0.5).
3. **The Missing Time Penalty:** If Agent 1 flagged that the time is missing, the Verifier multiplies the score by 0.9 (a 10% penalty) because we can't fully trust old/undated news.
4. **The Adversarial Flag:** If the source's reliability is less than 30% (0.30), the Verifier stamps a giant red `ADVERSARIAL` warning on the file.

### ⚖️ AGENT 3: THE CONFLICT SPOTTER (contradiction_detector.py)
**The Job:** Look in the Encyclopedia. Do we already know something about this subject?
**What it actually does:**
1. It searches the database for the exact `subject` and `predicate`.
2. **The Semantic Matcher:** If we already have "$5M", and the new claim says "five million dollars", the computer usually thinks these are completely different. Agent 3 uses a Python tool called `SequenceMatcher`. It compares the letters and words. If they are at least 82% similar, Agent 3 realizes they are the same fact and flags it as `CORROBORATION`.
3. If they are completely different (e.g., $5M vs $8M), it flags a `CONTRADICTION`.

### 🏛️ AGENT 4: THE CURATOR (memory_curator.py)
**The Job:** Make the final decision. Edit the Encyclopedia.
**What it actually does:**
*   **ACCEPTED:** If the claim is brand new and trustworthy, write it in the book!
*   **MERGED:** If Agent 3 spotted a Corroboration, don't write a new fact. Instead, take the existing fact and boost its confidence score (using a diminishing returns math formula: `new_conf = old + (1 - old) * 0.2`).
*   **UPDATED:** If a highly trusted source contradicts an old, weak source, the Curator crosses out the old fact (marks it `outdated`) and writes the new one in as `active`.
*   **DOWNGRADED:** If two highly trusted sources disagree (Equal Conflict), the Curator panics. It lowers the confidence of BOTH facts because it no longer knows who is telling the truth.
*   **REJECTED:** If a claim has the `ADVERSARIAL` stamp, or if a weak source tries to argue with a strong source, the Curator throws the claim in the garbage.
*   **FORGOTTEN:** (See Memory Overflow below).

## 3. ADVANCED FEATURE: MEMORY OVERFLOW (THE FORGETTING CURVE)

If the AI just remembers everything, its hard drive will eventually explode. 

**How we solved this:**
The Memory Curator has a strict capacity limit (we set it to 25 items for the demo). 
Every time a new fact is accepted, the Curator checks if the memory is full. If there are 26 items, it triggers an "Eviction".
1. It scans the entire database.
2. It looks for facts that have a `confidence` lower than 20% (0.20) and no corroborating sources.
3. It changes their status from `low_confidence` to `forgotten`. 
4. The system has successfully purged useless noise to make room for important data.

## 4. HOW TO READ THE CONSOLE OUTPUT

When you run `python main.py`, lines print out rapidly. Let's dissect one complex line:

`[11] C004  | [v] DOWNGRADED | [MODERATE_TRUST] | Startup A            | $8M in 2022`

*   `[11]` - We are currently processing the 11th line of the JSON file.
*   `C004` - This is the unique Claim ID.
*   `[v] DOWNGRADED` - The action taken by Agent 4 (The Curator). The `[v]` is just a visual arrow pointing down. It means a conflict occurred and we lost confidence in our memory.
*   `[MODERATE_TRUST]` - The verdict from Agent 2 (The Verifier). The source reliability was okay, but not perfect (between 30% and 75%).
*   `Startup A` - The subject.
*   `$8M in 2022` - The object of the claim.

## 5. THE OUTPUT FILES EXPLAINED

The code doesn't use a massive SQL database. It uses clean, lightweight JSON files.

### 📁 memory_store.json (The Encyclopedia)
This is what a saved memory looks like inside the file:
```json
"Startup A | raised funding of": [
  {
    "object": "$8M in 2022",
    "confidence": 0.706,
    "status": "active",
    "sources": ["Reuters", "Bloomberg", "Forbes"],
    "corroboration_count": 6
  }
]
```
Notice how it doesn't store 6 different entries. It stores ONE entry, lists all 6 sources, and keeps a single `active` confidence score.

### 📁 change_log.json (The Explainability Engine)
If a judge asks: *"Why is the confidence 0.706?"*, this file holds the answer. It is an immutable, append-only ledger of every mathematical change.
```json
{
  "timestamp": "2024-01-02T00:00:00+00:00",
  "action": "DOWNGRADED",
  "reason": "Equal-confidence conflict between '$5M in 2021' and '$8M in 2022'. Both confidence scores reduced. Memory is uncertain."
}
```
This file is the most important part of the Hackathon. Large Language Models (like ChatGPT) "hallucinate" because they can't show their math. **Our system is fully explainable.**

## 7. DEEP DIVE: HOW TO ANSWER JUDGE Q&A

When the judges come to your table, they will try to poke holes in your logic. Memorize these answers:

**Q: How does your AI handle trolls or fake news?**
A: "Agent 2 has a hard-coded Trust Threshold. If a source's reliability score is below 30%, it is instantly flagged as ADVERSARIAL. Agent 4 will automatically REJECT any adversarial claim that tries to change our memory."

**Q: What if someone says '$5M' and someone else says 'five million dollars'? Does your memory duplicate?**
A: "No. We use a Sequence Matcher algorithm. If the incoming object text is 82% similar to the existing object text, Agent 3 flags it as a Corroboration, not a Novel claim. It safely merges them."

**Q: If you have two highly trusted sources saying completely different things, what does the AI do?**
A: "It doesn't guess. If the system detects an 'Equal Confidence Conflict', it issues a DOWNGRADE action to both facts. The confidence score of both beliefs drops dramatically to reflect that the system is now uncertain. It waits for a tie-breaker source."

**Q: Will your JSON file eventually get too big and crash the server?**
A: "No. We built a 'Forgetting Curve'. When the memory array hits a set capacity, the Curator triggers an eviction cycle. It looks for the weakest facts (low confidence, zero corroborations) and changes their status to 'FORGOTTEN', keeping the active memory lean and fast."

## 9. TECHNICAL CHALLENGES WE OVERCAME

If you want to sound incredibly technical, mention these hurdles:

**Hurdle 1: Temporal Ordering (The Missing Timestamp Problem)**
*The Problem:* The dataset had claims that didn't have a `timestamp`. If we processed them in random order, our chronology would break.
*The Fix:* We wrote a pre-parser in `main.py` that sorts all claims by ISO8601 strings, and explicitly forces any claim with a `null` timestamp to be processed *last* (assigned the year 9999 for sorting purposes).

**Hurdle 2: The Diminishing Returns Problem**
*The Problem:* If 100 people say $5M, the confidence shouldn't exceed 100%. If we just added numbers together, we would break the math.
*The Fix:* We implemented a diminishing returns algorithm: `new_confidence = old_confidence + ((1.0 - old_confidence) * 0.2)`. This ensures that confidence asymptotes towards 1.0 (100%) but never breaches it, mathematically mimicking human certainty.

**Hurdle 3: Windows Encoding Errors**
*The Problem:* Windows PowerShell tries to use `cp1252` encoding, which crashes when it tries to print arrows (`→`) or emojis to the terminal. 
*The Fix:* We injected an IO wrapper at the top of `main.py` (`sys.stdout.reconfigure(encoding="utf-8")`) to force PowerShell to accept UTF-8, ensuring a beautiful, crash-free terminal experience.
